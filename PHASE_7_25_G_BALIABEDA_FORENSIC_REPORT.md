## 3. Root Cause

1. **Unchecked 7-Digit Suffix Matching**: `VerifiedBhulekhCatalog.lookup()` assumed that the last 3 digits of any 7-digit GIS village code directly equal the Bhulekh Mouza number, without verifying that the candidate name aligns phonetically or normalized with the requested village name. For `0704027` (`G_Baliabeda`), `Mouza 27` is `ବଡ଼ ଡ଼େରା` (`bddr`), whereas the real village is `Mouza 331: ବଳିଆବେଡ଼ା` (`blbd`).
2. **Stats Counter Ingestion in RoR Verification**: When portal DOM labels are not present, fallback regex extracted `"30"` from `"No. of Districts : 30"` as the district name.

## 4. Fix Applied

1. **Name Consistency Validation on 7-Digit Codes ([`resolvers/bhulekh_identity_resolver.py`](file:///Users/uday/Documents/MyBhoomi/BhulekBackend/resolvers/bhulekh_identity_resolver.py))**:
   `VerifiedBhulekhCatalog.lookup()` now validates that candidate records from 7-digit ID matching align phonetically, by consonant skeleton, or normalized with the requested village name. When there is a conflict (such as `Baliabeda` vs `ବଡ଼ ଡ଼େରା`), the lookup rejects the false ID match and proceeds down the hierarchy to Level 6/7 (Consonant Skeleton match), which uniquely and deterministically selects `Mouza 331` (`ବଳିଆବେଡ଼ା`).

2. **Sanitized District/Tahasil Fallback Parsing ([`scrapers/bhulekh_scraper.py`](file:///Users/uday/Documents/MyBhoomi/BhulekBackend/scrapers/bhulekh_scraper.py))**:
   Updated text extraction to ignore page statistics ("No. of Districts", "Number of Tahasils") and pure numeric strings.
